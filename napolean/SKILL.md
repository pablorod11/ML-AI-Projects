# Napolean

One commander owns the result. Specialists receive bounded missions. Scale the process to the task; a small edit stays inline.

## Establish the mission

Read the request, applicable repository instructions, and relevant source. State the outcome, constraints, acceptance evidence, and material unknowns briefly. Follow user and host authority before this skill or its dependencies. Invocation does not authorize publishing, messaging, configuration changes, or unrelated installations.

Resolve named skills from the host catalog and read their current instructions before applying them. Use `using-superpowers` for process selection: brainstorming for new behavior, systematic debugging for failures, and planning for substantial work. Respect existing approvals; do not restart discovery already settled in the conversation.

## Reconnaissance and specialist selection

Read [references/integrations.md](references/integrations.md) when selecting a dependency or handling one that is missing.

Use Graphify for unfamiliar repository relationships when mapping will reduce uncertainty. Inspect installed capabilities and current documentation before choosing commands. Check graph freshness against the current revision and modified files. Follow graph findings to actual source and callers; label inferred edges. A graph is navigation evidence, not proof that a caller is absent. Fall back to `rg`, manifests, and source inspection when unavailable, and disclose that Graphify did not run.

Load only relevant Vercel agent-skills: React performance for React work, composition guidance for component APIs, and other specialties for their actual domains. Route UI work through `design-workflow`, preserving established identity unless redesign was requested. Avoid duplicate audits when that workflow already includes the same guidance.

## Command and delegation

Use available subagents when independent missions justify coordination cost. Work inline for trivial or tightly coupled tasks, or when delegation is unavailable or forbidden.

The commander retains requirements, dependency order, shared contracts, integration, and final verification. Before parallel edits, settle shared schemas and assign a single owner for shared files. Each mission contains:

- Objective and acceptance criteria.
- Relevant inputs, source paths, and agreed interfaces.
- Owned files and permitted side effects.
- Dependencies and verification to run.
- Required return: changes, evidence, unresolved claims, and blockers.

Respect the host's actual concurrency limit, reserving a slot for the commander. Use minimal relevant context. Workers do not recursively delegate unless explicitly assigned that authority within the same budget. Never create user-visible chats as internal workers. Reuse the same worker for fixes. Continue independent work while workers run; reconcile conflicting reports against source and runnable checks.

## Build and verify

Apply Ponytail's simplicity ladder: existing project code, standard library, native features, installed dependencies, then minimal new code. Preserve requested behavior, accessibility, validation, and error handling. Simplicity does not replace understanding the flow.

Apply Euclidean verification to explicit claims: name definitions, premises, sources, and conclusion; distinguish facts from assumptions. Check units and arithmetic. Use VALID only within the checked model, INVALID for contradictions, and UNVERIFIED for missing support. Its capacity checker covers its documented capacity schema only; it cannot prove general production safety.

Inspect worker changes and run checks appropriate to the integrated result. Record exact check outcomes and limitations. Agent agreement, graph edges, installation success, and test existence do not establish correctness. Repair in-scope failures; report a concrete blocker when further progress requires missing input.

## Deliver

Use Caveman for concise chat while preserving negations and technical payloads. Use Humanizer in embedded mode for prose deliverables. Saved documents, comments, and PRs use full natural language. Preserve commands, code, paths, numbers, citations, and uncertainty. A requested explanation takes precedence over brevity.

Return the result, verification evidence, and material remaining limitations. Do not claim a dependency ran when its fallback was used.
